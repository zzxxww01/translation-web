# 深入复查：版本、审校、术语、存储与外部资源

本轮是在 `80fa678` 的业务版本上继续复查，不替换默认模型、不合并 main、不执行生产部署。

## 修复内容

- **审校版本与完整性**：未绑定版本、部分覆盖、NaN/Infinity/浮点溢出不作为有效审校。新版复核会比较具体问题位置、类别与严重程度，不只统计 high+critical 总数。修订被拒绝时不能同时返回 passed；写入失败退回初稿时，译文、token 和审校也一起退回同一版本。
- **真实格式路径**：无行内格式的原文也检查模型自行生成的隐藏 token。精修失败不再因为可见文字未变而误认作安全无操作。确认译文缺少格式数据时不借用旧草稿的 tokenized_text。词语规范化不改动 CODE/MATH、代码、URL。
- **中文与术语上下文**：审校/精修保留术语的 strategy 和释义；移除禁止 token 在段内随中文语序移动的残留指令。正文首现不由来源说明或其他元数据占用；首现计划、段落 ID 映射贯穿初译和复核。批量翻译接收已批准的表达规则。
- **规则与热更新**：新增/删除都使用项目已有 portalocker 跨进程锁，锁失败不会无锁写入；原子写入成功后才更新独立缓存副本，读取损坏文件时不以空库覆盖。超长单条规则不阻断其他规则；不再因字符串高度相似而吞掉只有否定词不同的指令。模板 include 验证失败不会污染正在使用的注册表。运行固定已批准规则并保存摘要，恢复时使用同一快照，不把运行过程中新增的偏好混进后半篇。
- **外部图片读取**：HTML 导入、文档图片下载、公众号图片读取共用有大小限制的公共 HTTP 客户端。每跳重定向单独校验，实际连接使用已校验的数值 IP，HTTPS 继续验证原主机名，资源下载不沿用模型通道的代理/凭据。内部/共享/多播地址拒绝；过大、空、截断或有歧义的响应拒绝。只在受信任根目录内复制本地资源；公众号只读取当前项目图片，并返回自己的临时副本，避免调用方清理时删除原文件。下载完成后原子替换，不缓存半截文件。
- **前端依赖**：使用 npm 的兼容版本解析更新锁文件，不手写 integrity，也不使用 `--force` 跨主版本升级。修正升级后检查器指出的 useMemo 回调写法。

## 验证方式

本地恢复的源码快照测试：1027 passed，2 skipped。新增 60 个测试场景，覆盖部分复核、严重性升级、同数新错误、错误回退绑定、格式标记、模板失败重载、规则写入失败、首现、并发线程快照，以及重定向/DNS/IP 固定/大小限制/路径越界/临时文件所有权。网络安全测试使用模拟传输，不访问真实内部地址。

源码快照不包含仓库根目录的所有测试和 main 后续新增测试，完整仓库验收以本 PR 最新 CI 为准。发布前再次执行 Python 编译、应用导入、完整后端测试、前端 lint/test/build 和依赖扫描。

候选依赖锁文件在诊断运行中，npm audit 从 21 个报告项降为 0；最终数量及测试结果见 PR 验证记录。安装器/扫描器本身报错不会被表述为修复成功。

## 验证边界

没有执行真实付费模型质量评测，也没有完整浏览器端到端或生产环境验收。单元测试保护的是协议与已构造场景，不证明译文一定自然或绝无新错。匹配审校问题使用保守的原文片段/类别判据，歧义情况保留初稿待复核。

公共资源读取使用 OS DNS 解析器及连接/读取超时；生产环境还应实施网络层出站限制。固定 IP 防护不改变可信模型服务的代理配置。安全的本地图片需要放在源文档目录或当前项目目录中，不再接受任意服务器绝对路径。

新版前端检查器仍可能报告现有 Hook 警告；MathJax 的 eval 和较大 bundle 警告不能等同于本次 npm audit 漏洞，也不应通过关闭检查器掩盖。依赖扫描仅覆盖扫描时数据库中已知的风险，并非“绝对安全”证明。
