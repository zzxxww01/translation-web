## 八项建议对应的实现

| 项目 | 实现与边界 |
| --- | --- |
| 阶段及批次续跑 | 有效初译批次、源译审校、修订批次分别保存内容寻址检查点。审校失败复用初稿，修订失败复用审校，复核失败复用修订候选。候选缓存不是正式译文或通过标记。 |
| 工件有效性 | 项目内按原文、结构、提示词与规则快照、实际模型路由、阶段参数、上下文/术语匹配指纹；不再以目录最新时间或已经有译文作为分析复用的依据。全文分析尚未开始正文也能复用。部分失败的分析不能缓存为完整成功。 |
| 预扫描 | 每块仅注入正文命中的术语，候选再与全量词库归并；并行模式冻结术语基线，有界并发纯抽取，按原文顺序应用候选及冲突。默认仍串行。启用检查点时会对已译章节的原文恢复术语基线，命中缓存不再调用模型，不重译/覆盖人工正文。 |
| 阶段/运行预算 | 时间、逻辑生成次数、可选估算 token 预留总量；嵌套适配器不重复计数，各阶段不能重置运行总额。HTTP 尝试另受既有最多四次路由计划控制。预算拒绝保存候选，返回明确的 `paused/pause_reason`，不伪装完成。 |
| 完整请求打包 | 初译、普通章节模式和定点修订先渲染完整提示词，计入规则、术语、格式和上下文；超限批次递归拆为更小的 ID 集合。每次实际 generate 仍检查完整请求；单段或整章复核太大则明确待处理，不截断原文、不缩小复核范围。 |
| 阶段模型 | `model_scope=all` 保持旧的全流程覆盖语义；`draft` 只覆盖正文，预扫描、标题、来源、审校按 profile/阶段路由。独立 facade 绑定温度与输出参数，不修改共享客户端；相同物理模型的不同别名不误当同一路由。 |
| 紧凑审校 | 显式 `compact_review=true` 时只合并重复问题说明、取消可选评分；仍保留原文证据、译文位置、严重性、问题影响与修正建议。沿用同一证据校验与完整审校；没有评分不以 0 分触发自动学习。默认关闭。 |
| 增量本地读取 | 已解析章节按文件身份/纳秒时间戳/大小缓存并深拷贝返回，原子替换或人工写入使缓存失效；损坏文件依旧报错。缓存最多 64 章/按文件字节估算 32 MiB，单章超过 2 MiB 不存。术语匹配记录只重算变化的章节；最终仍重建可信前文、使用原有乐观版本合并，避免 AI 临时记录污染后文。 |

## 恢复状态和保护

`TranslationRecord` 新增 `quality_status / quality_version / quality_policy`。非空初稿仅表示文字存在，四步法续跑仍检查待完成的质量阶段。`review_pending`、`revision_pending`、`verification_pending`、`manual_review` 都不是通过。通过记录必须匹配源译哈希、当前策略和可安全导出的格式；人工确认内容不被后台自动重译。普通模式不凭空获得四步法质量认证。

`artifacts/stage-cache-v1` 只包含候选/步骤工件，写入前做解析、契约与内容哈希校验；跨实例文件锁合并相同的并发工作，锁等待可响应期限与取消。损坏/旧 schema/输入变化是 miss，不把缺字段当无问题。显式 `retranslate_scope=section/all` 绕过缓存读取，用户要求重译不会收到旧答案。无变化且有效的步骤才复用。

启用检查点的升级首次运行可能补做旧初稿未记录过的审校，旧版本没有保存的批次不能恢复。已存在的不兼容 prompt-bundle 继续明确拒绝混用版本，须由用户选择新运行策略；不会悄悄覆盖旧稿。检查点目前没有自动 TTL 清理，运维应按备份/项目保留策略管理；删除检查点只影响后续复用，不会删除正式译文。

## API 使用

`POST /api/projects/{project_id}/translation-workflow` 的可选 `efficiency` 字段；旧客户端不传仍有效。前端 API 与统一启动 hook 支持透传，不在本轮增加新的设置面板。

```json
{
  "method": "four-step",
  "model": "your-configured-body-alias",
  "retranslate_scope": "resume",
  "efficiency": {
    "stage_resume": true,
    "prescan_concurrency": 2,
    "model_scope": "draft",
    "profile": "default",
    "compact_review": false,
    "max_stage_seconds": 1800,
    "max_stage_calls": 64,
    "max_run_seconds": 21600,
    "max_run_calls": 1024,
    "max_request_input_tokens": 24000,
    "reserved_output_tokens": 8192
  }
}
```

并行和紧凑审校需要实际语料验收后选择开启，不会默认换低价模型、跳过保真检查或改动中文连接词规则。独立术语预检任务在正文运行之前，由原有任务服务管理，不属于 `translate_project` 预算范围。

## 预算与估算限制

- `max_run_estimated_tokens` 是输入估算加输出预留，计逻辑生成，不是人民币/美元账单上限；失败的传输尝试可能额外计费。精确费用仍须实际价目表和供应商用量对账，本轮不提供货币硬上限。
- 输入估算覆盖最终 prompt，但仍是 UTF-8/ASCII 启发式，不冒充供应商 tokenizer。`RequestBudget` 提供近阈值精确计数回调扩展点，未默认增加计数 API 请求。可通过 `max_context_tokens` 显式配置实际窗口，配合输出预留，不按模型名字猜值。
- 总阶段时间包含配额等待与退避，传输共享剩余时间。取消 Python future 无法撤销已受理请求；检查点阻止晚到候选作为已完成步骤写入。
- 预算耗尽结果为兼容既有任务协议保留 `status=failed`，额外返回 `paused=true, pause_reason=budget_exhausted`，错误说明支持继续；不是已经实现新的暂停/恢复设置界面。
- 增量读取只减少解析/术语匹配，不取消保存前重新核对版本。没有默认开启跨项目结果缓存、供应商 Batch API、增量审校或低价模型自动降级。

## 验证

离线回归覆盖：中断批次不重做、失败审校/修订/复核只续所缺步骤、已存初稿补审、强制重译不回放、分析先完成但无正文仍复用、错误分析不当成功、上下文/源文/术语/模型变化失效、并发只生成一次、取消后不写检查点、完整请求超限拆批及单段拒绝、源译证据校验、原文顺序归并、预算拒绝无多余调用、配置透传、文件损坏/人工更新不被缓存掩盖。前端测试验证显式选项透传和跨请求不串配置。

测试翻译均为模拟响应，不代表真实中文质量或账单改善。完整后端、前端及 Chromium 结果以本 PR 对应提交的 CI 工件为准，不借用父 PR 的测试数字。
