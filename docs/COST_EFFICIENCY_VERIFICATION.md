## 成本计量不能等同账单

`api_calls` 是应用记录到的已完成 provider 尝试，不保证每条都真正到达上游：配置、配额或截止时间检查也可能在 HTTP 发出前终止。失败请求没有返回 usage、任务关闭后迟到的 worker 用量及进程重启后未落盘的统计均可能不完整。供应商已受理的请求不能靠取消 future 撤回。

离线 `cost_report` 只对所提供工件中的已知用量、精确 provider_id/model 与所选平价计价期做估算，始终标记 `invoice_complete=false`。未知用量/缺失价格不按零费率处理；不同币种不相加。缓存写入、缓存存储、工具、阶梯价格、中转附加费、税费及上述未观测用量须另行核算。建议按供应商 request ID 与实际账单对账，并建立持久化事件账本。

## 上线时必须检查

- 共享截止时间约束一次生成内的尝试、配额等待与退避，不是已经实现整篇文章的货币预算。配置中原本未生效的输出上限现在生效，尤其观察思考模型的截断率；必要时按真实模型调整。
- provider 配额在单进程内共享，多 worker/多实例须接入统一的 RPM/TPM/并发协调；不能把单进程保护当成全局限流。
- 初译的字符打包预算是启发式，不能证明连同术语、上下文和输出后必定适合模型窗口；单个超长段落没有被截断隐藏。
- 固定前缀只是缓存准备，没有自动启用供应商所有缓存能力，也未启用跨项目结果复用、供应商 Batch API、低价模型自动降级或增量审校。相关建议见 `COST_EFFICIENCY_AUDIT.md`。
- 完整源译审校与修改后复核仍保留。单测和模拟浏览器测试不能证明中文质量提高或生产费用降低。
