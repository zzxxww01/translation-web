# 中文质量与提示词链路 v2

本变更以 main `34290d851ee3fdc7ff61c5197e28dd83c3928855` 为基线；保留现有模型配置、故障转移、段落 ID、人工编辑冲突保护与分段策略。不宣称模型翻译质量已经实测提高。

## 改动

所有原有 36 个业务模板迁入共享保真/中文成文/格式/修订/职场模块；补齐命名的内联任务。`task_builders` 为 Gemini 和 VectorEngine 统一业务提示词与上下文。公共接口保持原形，已迁移的构造器执行严格参数检查。

中文成文不再硬删连接词、强制一句一事或按固定字数拆句。重点处理机械把/将句、多层前置定语、关系紧密的碎句、主语指代与条件范围。自然把字句保留；不以把字数、句长或成语数代替可读性。

初译允许自然重组；编辑和精修限定当前段落，只修有来源的问题。批量输出必须按 ID/index 对齐，拒绝重复/未知身份及无法解释的结构。CODE/MATH 内容不变，行内 token 允许随本段语义调整位置。标题保留内部冒号，错误/截断 JSON 不再变成空问题列表。

四步法的一次有界定点修订后，内容变化会触发源译对照复核。审校绑定源译哈希；格式失败、复核失败或严重问题增加时保留初稿，并明确标为未通过/降级。无具体问题不因分数偏低重写整章。评分仅作诊断，严重性而非问题类别决定阻断。完整复核增加一次模型调用，需考虑成本。

术语首现按正文原文顺序分配，不按并发完成顺序。未给出译文的预扫描不再假造“已使用译法”；无法核验的候选待确认。未知术语策略保守保留。所有自动规则学习先入待审候选，显式批准后才激活；规则页面提供来源与批准/拒绝操作，历史有效规则保留。

标题只使用输入支持的事实，八个槽位兼容保留但不强造八种论点。帖子支持 `include_hashtags=false`，局部优化默认不重新推荐标签。Slack 的 A/B/C 对应简洁/标准/正式；保留历史“友好”输入，语气变化不得变成新增承诺。没有原文的润色不声称核验忠实性。

## 版本与恢复

每个运行记录 `prompt-bundle.json`（模板、构造代码摘要、编辑配置版本）。运行内通过 contextvars 固定模板，线程继承；部分旧任务的版本不兼容时拒绝悄悄混用，保留已生成结果，需显式选择新的全量重译。不会自动重译或覆盖用户确认内容。术语分析、章节上下文和审校历史保存在既有 run artifacts 中。

## 验证

离线测试覆盖全部模板渲染、Provider 同任务等价、完整上下文、JSON/ID/index 约束、旧版本审校拒绝、无问题不改、失败回退文本/token一致、规则候选与首现分配。`tests/chinese_quality_v2_cases.json` 是 40 条人工构造的开发验收样例，不是模型实测输出。参考译文只是一个可接受版本；语义检查为主，不按同义措辞或空格机械判错。

真实模型评测默认禁用：`RUN_LLM_TESTS=1 pytest tests/unit/test_chinese_quality_v2_corpus.py -q`。此命令使用已配置服务和付费模型。保护字符串检查只是一层验收，仍需对保存的输出逐项盲评忠实、逻辑、自然度，尤其验证连续编辑的稳定性。不要根据单元测试通过就认定中文风格已经稳定。

## 操作

新增 API：GET `/api/projects/translation-rule-candidates`；POST `/api/projects/translation-rule-candidates/{id}/approve` 或 `/reject`。批准意味着加入全局规则，界面会明确告知。模型生成候选默认不生效。

部署需同时更新后端与前端，并安全暂停旧任务后重启服务加载配置。此分支不自动合并 main、不自动部署。
