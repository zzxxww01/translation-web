## 配置与操作

`POST /api/projects/{project_id}/translation-workflow` 在原有参数之外接受：

```json
{
  "method": "four-step",
  "model_scope": "draft",
  "model_profile": "default",
  "retranslate_scope": "resume",
  "efficiency": {
    "resume_stages": true,
    "prescan_concurrency": 3,
    "stage_timeout_seconds": 1800,
    "max_stage_calls": 64,
    "run_timeout_seconds": 14400,
    "max_run_calls": 2000,
    "compact_review": false
  }
}
```

`model` 仍由用户提供已配置的模型别名。scope=all 时所有阶段使用用户选择，scope=draft 时只覆盖正文初译；normal 模式的前端不启用四步法专用选项。`model_profile` 使用仓库已有 default/fast/premium 配置，本轮不改这些配置的模型映射或默认质量标准。

窗口限制来自所使用供应商的实际模型定义，可在模型或阶段配置增加上述 token_limit 字段。模型只分别定义输入/输出窗口时，不应错误填写“共享上下文窗口”。可注入 local_token_counter 做精确的本地模型计数，结果按模型与输入摘要进行有界缓存；实现不会为每次请求再追加远程计数调用。fallback 的各物理路由按自己的限制再次检查。

预算默认值是安全执行边界，不是最佳吞吐配置。长文可能需要调高文章或阶段预算后恢复；不能为过预算切换到“未审校也算成功”。请求未发送就因本地窗口约束被拒绝，不消耗模型 admission；真实 transport 重试共享所有父预算。多进程限流仍沿用前轮注明的边界，不把此处的单进程计数冒充跨机货币控制。

检查点位于项目的 `artifacts/work-checkpoints-v1`，最大 1024 条，每条至多 8 MiB，原子替换、文件锁、拒绝符号链接、只保留已校验结果。检查点包含文章派生结果，属于用户数据；应使用项目相同的访问隔离和备份策略。命中统计独立于模型调用数，不把命中一次计算成一次付费调用。清理缓存只影响复用，不删除正式译文。

原始章节与候选译文持久化仍是正式内容的事实来源。检查点仅复用步骤的结果，不能绕过当前版本验证、审校门禁、格式校验、人工内容冲突或最后的原子合并。

## 验证方案

新增 `tests/unit/efficiency/` 中 75 条离线专项测试，覆盖：

- 跨实例读取、深拷贝、跨项目隔离、指纹/规则/模型变化失效、显式重译绕过；损坏/超大/伪造身份/符号链接缓存拒绝与写盘失败。
- 并发 admission 原子性、嵌套预算不重复计数、父截止时间、取消、最后一个允许响应与检查点保留、类型化错误恢复。
- 初译批次失败、审校失败、修订后复核失败的恢复；局部有效响应保留；完整输入超限时初译和修订拆批且索引不串位。
- 质量证明绑定源文、译文与策略；legacy AI 初稿补审；人工已确认/未确认内容保护；分析完成但无正文也允许恢复。
- 预扫描网络有界并行、严格有序归并、不可变基线、失败不写入/不应用、预算终止；关键词边界筛选。
- 深拷贝章节缓存、同长度原子替换识别、损坏新文件不得复用旧结果；phase 参数和模型作用域、请求参数验证。

前端新增一条请求契约测试，验证高级选项传递后仍保持 resume 范围，不自动变成整篇重译。完整后端、前端 lint/类型/构建、既有 Chromium 模拟接口回归及依赖审计都需在远程 CI 再运行；真实模型评测继续显式关闭。最终数字以 PR 对应的 CI 日志为准，不使用本地结果冒充远程验证。
