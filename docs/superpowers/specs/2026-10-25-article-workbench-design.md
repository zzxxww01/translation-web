# 文章工作台：设计稿、PRD 与技术方案

日期：2026-10-25　状态：v1 直接实现上线，试用后迭代（用户明确不需要事先确认）

## 1. 背景

用户的真实工作流只有一条线：

1. 在文章库里看最近有什么文章；
2. 选一篇导入，**同时**跑网页版翻译和第二个译本；
3. 英文、译本 1、译本 2 三版对照，逐段确认、修改；
4. 导出要用的那一版。

现状把这条线拆成了三个互不相通的页面：「文章库」导入完要切到「长文翻译」，长文页得先选段落才看得到译文；Claude 的译文躺在 Claude 页的文件里，没法和网页版放在一起比，改了也存不回去。

2026-10-25 上线实测还确认了一个约束：**Claude 对付费文章拒绝全文翻译**（原话：「全文精翻会把整篇付费文章原样转成中文，不管译文给谁看，这一步我都做不了」），只给一份中文导读。SemiAnalysis 的文章大多是付费的，所以「译本 2」不能只指望 Claude。

## 2. 目标与非目标

目标：

- 一个页面走完一篇文章的全流程：选题 → 导入 → 两路翻译 → 对照编辑 → 导出。
- 三栏对照（英文 / 译本 1 / 译本 2），任意一栏可以收起；两个中文栏都能直接改、自动保存；任意一版都能导出。
- 译本 2 的来源可选：**换模型再翻一版**（默认 argon，付费文章也能用）或 **Claude skill**（Claude 愿意翻的文章）。
- 两路翻译都在服务器后台跑，关掉页面不影响；需要人操作（术语确认、Claude 提问）时页面上有明确提示。

非目标（v1 不做）：

- 帖子翻译、微信排版、Slack、工具箱不动。
- 旧长文编辑器不删：单段重译、质量报告、术语表这些进阶功能先从工作台「更多」进入旧编辑器。
- 三版之间的自动差异高亮、逐段「定稿」状态，留到试用后再定。

## 3. 用户流程

```
文章（默认首页）
 ├─ 左栏：文章列表（文章库 343 篇 + 自己的项目，一个列表，筛选：全部 / 未导入 / 已导入，可搜索）
 │
 ├─ 点未导入的文章 → 右侧文章卡
 │     中文标题、中文摘要、英文标题、日期、字数、付费标记
 │     [导入并翻译]   ☑ 网页版   译本 2：( argon 再翻一版 ▾ | Claude skill | 先不要 )
 │
 └─ 点已导入的文章 / 导入完成 → 工作台
       顶栏：标题 · 两路进度 · 待办提示条 · [导出 ▾] · [更多 ▾]
       三栏：英文 │ 译本 1（网页版）│ 译本 2（argon / Claude）
```

关键交互：

- **一次点击启动两路**。导入成功后直接进工作台，译文逐段出现，不用等全部完成。
- **待办提示条**：网页版在等术语确认时显示「网页版在等你确认术语，约 N 分钟后自动采用建议」；Claude 提问时显示「Claude 在问你问题」。点提示条打开右侧抽屉处理，处理完抽屉关掉，回到对照。
- **采用**：鼠标停在某段中文上，出现「用另一版这段」按钮，一键把另一版的这段抄过来再改。

## 4. 信息架构

顶部导航由 7 项变 6 项：

| 现在 | 之后 |
|---|---|
| 长文翻译、文章库 | **文章**（合并，默认首页） |
| 帖子翻译、微信排版、Slack 回复、工具箱 | 不变 |
| Claude | 不变：聊天、视频字幕、播客配音等 agent。文章的 Claude 译本任务也会出现在这里的任务列表里 |

旧地址都保留可用：`/document`、`/substack` 跳到 `/articles`；`/document/:id` 跳到 `/articles/:id`；旧编辑器挪到 `/document/:id/editor`（工作台「更多」里进入）。

- 三栏共用一个滚动容器，按段对齐成行：同一段原文和两版译文永远在同一行。
- 栏头固定在顶部：栏名、收起、导出这一版。
- 中文格子就是可编辑的文字：点进去直接改，停顿约 1 秒或离开格子时自动保存，格子右下角显示「保存中 / 已保存 / 保存失败（重试）」。
- 标题段按级别加粗放大；图片只在英文栏显示，中文栏留空。

## 6. 功能需求（PRD）

**F1 文章列表**
- 文章库文章和项目合在一个列表里。「全部 / 未导入」按发布日期倒序列文章库文章，「已导入」按最近更新倒序列所有项目（包括手动上传、不在文章库里的）。
- 每行：中文标题（还没生成时显示英文标题）、日期、付费标记；已导入的显示两路进度条。
- 搜索中英文标题。滚到底自动加载更多。
- 验收：343 篇都能翻到；导入后不刷新页面，这一行就变成「已导入」。

**F2 文章卡与导入**
- 未导入：显示中文标题、中文摘要、英文标题、副标题、日期、字数、付费，外链原文。
- 「导入并翻译」一次完成：导入 → 启动网页版 → 启动译本 2（按选择）→ 进工作台。
- 付费文章没填 cookie 时，直接在卡片里给出填写 cookie 的入口。
- 选 Claude 时提示「付费文章 Claude 通常不肯全文翻译」。
- 验收：从点按钮到进工作台不超过 10 秒；两路都在后台开始。

**F3 两路翻译**
- 译本 1 = 网页版四步法，默认模型（长文 3.8-flash）。
- 译本 2 = 二选一：
  - 换模型：用同一份原文建一个「孪生项目」，用指定模型（默认 `gemini-official-argon`）跑同一套四步法。术语预检自动采用建议，不打断用户。
  - Claude skill：把原文 HTML 交给 `four-step-translate`，Claude 的提问在抽屉里回答；跑完自动取回 `zh.md`、`en.md`，对齐到段落，存成孪生项目。没有 `zh.md`（比如 Claude 拒绝了）时，在栏里说明原因，并给出「改用 argon 再翻一版」按钮。
- 已经导入过的文章，工作台「更多」里可以随时补建或换掉译本 2。
- 验收：关掉页面再打开，进度接着显示；任何一路失败，栏头显示失败原因和重试按钮。

**F4 三栏对照**
- 按段对齐；栏可收起、可展开；收起状态持久化；至少留一栏。
- 翻译中的段落显示占位「翻译中…」。
- 验收：57 段的文章，三栏滚动不卡；一栏收起后另两栏自动变宽。

**F5 编辑与保存**
- 两个中文栏每段都能改；自动保存（停顿 1 秒或失焦）；保存失败给出重试；有未保存内容时离开页面要提示。
- 「用另一版这段」：把另一栏这一段抄过来并保存。
- 改动直接写进对应项目的段落（`confirmed`），导出、质量检查都认这个结果。
- 验收：改一段 → 刷新页面 → 还在；导出的 Markdown 里是改过的内容。

**F6 导出**
- 顶栏「导出」菜单列出：英文原文、译本 1、译本 2；每个栏头也有导出按钮。
- 下载 Markdown 文件，文件名沿用现有规则（中文标题_zh.md）。
- 质量检查拦下时（比如还有段落没译完），提示原因，并给出「仍然导出」。

**F7 Claude 页登录**
- 一个浏览器登录一次，记住一年，每天第一次用时自动续期。Claude 页能在服务器上执行任何命令，所以不能完全去掉登录。

## 7. 技术方案

### 7.1 数据模型：孪生项目

译本 2 不另造一套存储，而是一个**同源的孪生项目**：

- 用主项目的 `source.html` 新建一个项目，id 为 `{主项目 id}--{后缀}`（`--argon`、`--claude`）。同一份 HTML 解析出的章节 id 和段落 id（`p000`…）完全一致，所以两边按段落 id 一一对应。
- `ProjectMeta` 新增三个可选字段：`variant_of`（主项目 id）、`variant_kind`（`model` / `claude`）、`variant_label`（栏头显示的名字）。主项目新增 `claude_run_id`（关联的 Claude 任务）。
- 好处：导出、质量检查、术语表、进度、断点续译、编辑保存全部复用现有项目能力，零分叉。
- 项目列表默认不列孪生项目；删除主项目时连带删掉它的孪生项目。

### 7.2 后端接口

| 接口 | 说明 |
|---|---|
| `GET /api/projects/{id}/workbench` | 一次返回工作台所需的全部数据：主项目信息、各孪生项目（kind、label、进度、运行状态）、按顺序排好的段落行（id、章节、类型、标题级别、原文、图片地址、译本 1 文字、各译本 2 文字） |
| `PUT /api/projects/{id}/workbench/paragraphs/{pid}` | `{target, text}` 保存一段；`target` 是主项目或某个孪生项目 id。写 `confirmed`，限流 120 次/分钟（编辑频繁，不用确认接口的 20 次/分钟） |
| `POST /api/projects/{id}/variants` | `{kind: "model", model, label}`：建孪生项目并用指定模型启动后台四步法，术语预检自动采用（`LongformWorkflowStartRequest` 加 `auto_accept_terms`） |
| `POST /api/projects/{id}/variants/claude` | `{run_id, zh_markdown, en_markdown}`：对齐后建 `--claude` 孪生项目，把译文写进各段 `confirmed` |
| `PUT /api/projects/{id}/claude-run` | `{run_id}`：记下这篇文章对应的 Claude 任务 |
| `GET /api/projects/{id}/source-html` | 原文 HTML，前端拿去交给 Claude |
| 已有：`POST /api/projects/{id}/export?format=zh\|en` | 主项目、孪生项目都直接用 |
| 已有：`POST /api/substack/import`、`POST /api/projects/{id}/translation-workflow`、`GET …/translation-status` | 导入、启动、进度 |

### 7.3 Claude 译文对齐

`four-step-translate` 的产出是 `en.md`（它自己从 HTML 转的英文）和 `zh.md`，两者块结构一致（它的 QA 门禁检查标题、链接、图片数量对得上）。对齐分两步：

1. `zh.md` 与 `en.md` 都切成块（标题、段落、列表项、引用、图片、表格各成一块）。块数相同时按序号配对；不同时，用块类型序列做 `difflib` 对齐配对。
2. `en.md` 的块与项目原文段落做**单调对齐**（动态规划，O(块数 × 段数)）：分数是段落词集合在块里的覆盖率，一块可以对多段（列表、被拆开的段落），按顺序不交叉。一块对多段时，按行把中文拆给各段，行数对不上就整块给第一段。没对上任何段的块，并进前一个已对齐的段落，**中文一个字都不丢**。

结果写进孪生项目各段落的 `confirmed`；对齐统计（对上 / 合并 / 没对上）记在孪生项目元数据里，栏头显示。

### 7.4 前端

新功能目录 `web/frontend/src/features/articles/`：

| 文件 | 职责 |

| `components/ArticleSidebar.tsx` | 列表、搜索、筛选、无限滚动；复用文章库接口 |
| `components/ArticlePreview.tsx` | 文章卡、导入选项、cookie 入口 |
| `components/Workbench.tsx` | 顶栏、提示条、栏布局、抽屉 |
| `components/PaneGrid.tsx`、`ParagraphRow.tsx`、`EditableText.tsx` | 对齐行网格、可收起的栏、自动保存的编辑格 |
| `components/TrackDrawer.tsx` | 抽屉：术语确认（复用 `TerminologyReviewPage`）、Claude 任务（复用 `RunPanel`） |

- 进度：任一路在跑时每 4 秒拉一次 `workbench`；都停了就不再轮询。
- Claude 一路由前端编排：取 `source-html` → 交给 skill-runner 建任务 → `claude-run` 记下关联 → 任务结束后从任务文件里找最新的 `zh.md`、`en.md` → 交给 `variants/claude`。工作台打开时发现任务已结束但还没导入，会自动补导。
- 导航：`FeatureNav` 合并成「文章」；`router.tsx` 加新路由和旧地址跳转。

### 7.6 风险

| 风险 | 对策 |
|---|---|
| 服务器只有 2 GB 内存，两路同时翻 | argon 走官方 API、模型调用在远端，本机只多一个后台任务；发版后实测内存 |
| Claude 拒绝付费文章 | 默认译本 2 用 argon；Claude 不出 `zh.md` 时栏里说明，并一键改用 argon |

| 旧编辑器功能缺口 | 「更多」里保留旧编辑器入口 |

## 8. 第二版调整（2026-10-26，用户试用后的反馈）

- **译本 1 = 网页版，译本 2 = Agent（Codex / Claude）**。导入时四选一：两个都翻（默认）/ 只翻网页版 / 只用 Agent 翻 / 只导入；
  选到 Agent 时再选 Codex（默认，付费文章也肯翻）或 Claude。「换个模型再翻一版」从导入和工作台入口拿掉，已有的模型译本照常显示。
  网页版没开始时，译本 1 栏头有「开始翻译」。
- **图片三栏都显示**（之前两个译本栏只写「（图片）」）。
- **网页上没有「最终版 / 定稿」这个概念**（用户：「我现在实际上不用网页确定最终版…自动保存和手动保存都不能说明最终版」）。
  改了就自动保存，状态汇总到栏头（保存中… / 已保存 14:02 / N 段没保存上），段落里只在失败时标红给重试；
  顶栏「保存」（Ctrl/⌘+S）只是让正在改的那段立刻存下并确认都存好了，不做别的。
- **人工改动**（`src/services/article_edits.py`）：机翻初稿 = 段落里最新一条非 `manual` 的译文记录，现在 = `best_translation_text()`。
  两者本来就存在项目数据里，改动随时实时算，不需要任何「保存全文 / 定稿」动作：
  栏头「看你改了什么」按段逐字标出删改，可下载这篇；`GET /api/workbench/human-edits.jsonl` 导出所有文章、所有版本的人工改动，给以后优化提示词用。
- **Agent 的确认环节**：一轮结束在等确认时回复末尾带 `【等待确认】`，工作台据此显示「在等你确认」而不是去导入；
  10 分钟没回复自动按它的推荐继续（见 `skill_runner/README.md`「等确认超时自动继续」）。
- **文章列表**：筛选 全部 / 未导入 / 已导入，带篇数；「已翻译」不是并列的分类，而是已导入文章各自的翻译进度
  （还没翻 / 翻译中 N% / 等你确认术语 / 已译 N% / 已翻译，带进度条），网页版和译本 2 取进度高的那一版。
- **拉新文章**：进入文章页、刷新页面、点一篇文章、打开工作台时都自动去 Substack 看最新一页（两次至少隔 15 秒，`useAutoSyncArticles`），有新文章才提示；列表顶上的刷新按钮随时手动拉。
